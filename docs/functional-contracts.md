# PIXEL TOWN 기능 계약과 기준선

이 문서는 리뉴얼 중에도 유지해야 할 현재 동작을 기록합니다. 이번 단계에서는 계약과 테스트만 추가하며 게임 서버/화면 로직과 경제 규칙은 변경하지 않습니다.

## 교실과 플레이

| 계약 | 현재 동작 | 검증 기준 |
|---|---|---|
| 새 교실 | 교사 PIN으로 교실을 만들고 고유한 숫자 4자리 코드를 받는다 | 교사 화면에 4자리 코드가 표시된다 |
| 코드 입장 | 학생은 이름과 4자리 코드로 해당 교실에 입장한다 | 게임 화면이 열리고 플레이어 상태에 학생이 등록된다 |
| 인원 제한 | 한 교실에 학생 최대 30명을 등록한다 | 30명 접속 성공, 31번째 신규 학생 거부 |
| 재접속 | 연결이 끊긴 학생은 같은 이름으로 다시 접속해 기존 기록을 이어간다 | 이름이 같은 오프라인 플레이어의 상태가 복구된다 |
| 수업 상태 | 이동과 일반 경제 활동은 수업이 진행 중일 때만 허용한다 | 시작 전/일시정지/종료 상태와 진행 상태를 구분한다 |
| 이동 | WASD, 방향키, 터치 패드 이동을 서버 상태와 동기화한다 | 진행 중 이동하면 위치가 바뀌고, 맵/다른 화면에 반영된다 |

## 경제 학습 활동과 유지 기능

아래는 초등 6학년 경제 학습에서 다루기 쉬운 개념과 현재 게임 기능을 연결한 검토표입니다. 공식 교과서 문구를 대체하는 것이 아니라, 교실용 시뮬레이션의 활동 기준입니다.

| 학습 주제 | 유지해야 할 현재 활동 |
|---|---|
| 일과 소득, 세금 | `work`, 소득세 계산, 누적 수익/납부 세금 |
| 소비와 시장 교환 | 기본 상품 구매·판매, 학생 가게 상품 구매 |
| 예산과 금융 선택 | 예금·출금, 대출·상환 |
| 투자와 자산 | 주식 매수·매도, 회사 창업과 주식 발행, 부동산 구매 시도 |
| 생산·유통·창업 | 식품 가게/도매상 창업, 재료 입고, 도매 주문·영수증, 요리·재고·가격·판매 |
| 공동체와 경제 활동 | 학생 간 송금, 기부 및 세금 감면권 |
| 교사의 수업 운영 | 시작/일시정지/재개/종료, 공지·보너스·세율·가격·학생/가게 관리 |

경제 행동의 실제 허용 여부와 잔액·재고·세금 계산은 서버가 결정합니다. UI 개선 시에도 기존 Socket.IO 이벤트와 상태 필드를 호환성 기준으로 취급합니다.

## 재시작 후 데이터 보존 검토

현재는 교실별 JSON 스냅샷을 `DATA_DIR/pixel-town-save.json`에 원자적으로 기록합니다. 학생 자산·거래 관련 상태·주식·가게·재고·수업 설정을 복구하며, 재시작 시 접속 상태는 오프라인으로 바꾸고 실행 중이던 수업은 일시정지 상태로 복구합니다. 기본 저장 경로는 프로젝트의 `data/`이며, Render에서는 Persistent Disk를 `/var/data`에 연결하고 `DATA_DIR=/var/data`를 지정해야 재배포 뒤에도 보존됩니다. 이 방식은 단일 서버 인스턴스 전용이고 다중 인스턴스 간 동기화·자동 백업은 제공하지 않습니다.

| 선택지 | 장점 | 주의점 |
|---|---|---|
| 현재 JSON 스냅샷 | 의존성이 적고 단일 인스턴스에서 저장·복구를 시작할 수 있다 | 다중 인스턴스 공유·백업·복구 관리가 필요하며, 대규모 운영용 DB를 대체하지 않는다 |
| SQLite + 영속 디스크 | 로컬 단일 서버에서 트랜잭션과 구조화된 저장이 가능하다 | 디스크 연결·백업·배포/복구 절차가 필요하고, 여러 서버 인스턴스에서 공유할 수 없다 |
| 관리형 PostgreSQL | 영속성, 동시성, 백업, 다중 인스턴스 확장에 적합하다 | 서비스 설정/자격 증명/스키마 관리가 추가된다 |

다음 단계에서는 정기 백업·파일 손상 복구와 교실 코드 재사용 정책을 보완해야 합니다. 여러 인스턴스 또는 운영급 지속성이 필요해지면 관리형 PostgreSQL로 이전하는 것이 좋습니다. Socket.IO 연결 ID는 재시작마다 바뀌므로 학생 재접속 시 기존 사업체 소유자 참조도 새 연결 ID로 갱신합니다.

## 데이터 보존 테스트

`tests/e2e/persistence.spec.js`는 별도 서버 프로세스를 실행해 교실 생성·학생 입장·잔액 변경 후 서버를 종료하고 다시 시작합니다. 같은 교실 코드로 재접속했을 때 학생의 기존 잔액이 복구되는지 확인합니다. 재시작 시 진행 중 수업은 자동으로 일시정지되어 시간이 서버 종료 중 흘러가 버리는 것을 방지합니다.

## 기준선 테스트

```bash
npm run test:e2e
```

Playwright는 로컬 서버와 Chromium을 실행하고 교실 생성/코드 입장/이동, 대표 경제 거래를 확인합니다. 별도의 30명 부하 계약 테스트는 30개의 독립 Socket.IO 클라이언트를 동시에 연결해 서버의 접속 제한을 검증합니다. 따라서 브라우저 탭 30개의 렌더링 성능이나 실제 운영 호스팅 용량을 측정하는 부하 인증은 아닙니다.
